# Commit message format

Rules and sources: [code-style.md](code-style.md) section 5 (CO-01 to CO-14) and section 6 (PR-01). Checker: `bun tools/check-commit.ts`. Editor template: [templates/gitmessage](../../templates/gitmessage).

```text
type(scope)!: imperative summary of at most 72 characters

Problem: what was wrong or missing, and who sees it.

Change: what this commit does and why this approach. Name the line or
function that is the fix when the commit also refactors.

Verified: the commands run and what they printed; what was not run.

Fixes #123
Fixes: 54a4f0239f2e ("subject of the culprit commit")
BREAKING CHANGE: what to do instead
```

- Types: feat, fix, docs, chore, refactor, perf, test, build, ci, revert (read from `standard.toml`).
- Scope: the area noun of the change (install, http, css, docs). Omit it when the change is repository-wide.
- The summary completes "If applied, this commit will ...": `fix(install): keep the bin link of a native dependency`.
- Problem, Change and Verified are prose paragraphs; the labels are optional. Short, obvious changes (docs, typo) need no body.
- Trailers go last, one blank line before them. Allowed: `Fixes`, `Closes`, `Refs`, `Link`, `Reported-by`, `Co-authored-by` for a human, `Signed-off-by` for a human when the repository asks for a DCO, `BREAKING CHANGE`. Not allowed: attribution to an assistant or a bot, `Generated by`, `Assisted-by`.
- Wrap prose at 72 columns in direct commits. A squash message built from a pull request body is Markdown and is not wrapped.
- Never put secrets, developer-machine paths or private hostnames in a message.

## Examples

Good:

```text
fix(http): resume a partially written request head from the same bytes

When a request head does not fit in one write, the client serialized the
whole head again on every writable event. Keep the serialized head until
all of it is written and resume from those bytes.

Verified: cargo test -p http write_head (new test, fails before the change).
```

Bad, with the rule it breaks:

- `Fix bug` (CO-01, CO-02: no type, says nothing)
- `fix: fixed the leak.` (CO-02: not imperative, trailing period)
- `feat: add search\n\nGenerated with <assistant>` (CO-10)
- `chore: update` (CO-02: vague)

## Use

```sh
git config commit.template .gitmessage                              # editor template, after copying templates/gitmessage
bun tools/check-commit.ts --message-file "$1"                       # as .git/hooks/commit-msg, if a repository wants a local gate
bun tools/check-commit.ts --range origin/main..HEAD                 # before pushing a series
bun tools/check-commit.ts --title "fix(http): resume a request head" # a pull request title
```

Forks that track an upstream keep the upstream's style: pass `--style=area`. Repositories that ask for a DCO pass `--dco`.
